## Telegram-бот для бронирования помещений университета

Клиент к [бэкенду лабораторной работы №2](https://github.com/alll1lll1lll/lab1-nosql): бот не хранит данные заявок сам,
а работает через его REST API. Через бота студенты и преподаватели бронируют аудитории и коворкинги,
а администратор рассматривает заявки.

### Возможности
- регистрация (ФИО и роль: студент или преподаватель) и вход по номеру ИСУ;
- просмотр помещений по типу (аудитории, коворкинги) и корпусу, занятость комнаты на выбранную дату;
- бронирование в пошаговом диалоге с кнопками: комната, категория, название, дата, время, число участников, телефон;
- временная корзина заявок: позиции собираются в ней и отправляются на рассмотрение одной кнопкой;
- если корзина недоступна (не работает Redis на бэкенде), заявка создаётся напрямую как черновик, и её можно отправить на рассмотрение кнопкой;
- свои заявки, карточка заявки с действиями (отправить на рассмотрение, удалить, посмотреть занятость комнаты);
- студенты не видят коворкинги «только для преподавателей»;
- для администратора: все заявки пользователей, одобрение и отклонение кнопками, список пользователей, добавление пользователей (в том числе администраторов).

Почти всё управляется кнопками под сообщениями, вводить команды руками не обязательно.

### Основные команды
| Команда | Что делает |
|---|---|
| `/start`, `/help` | начало работы и список команд |
| `/register` | регистрация (пошаговый диалог) |
| `/login <ИСУ>` | войти по номеру ИСУ (в том числе после перезапуска бота) |
| `/rooms` | помещения: тип, корпус, комната |
| `/room <id> [ГГГГ-ММ-ДД]` | описание комнаты и её занятость на дату (по умолчанию сегодня) |
| `/book` | новая заявка (пошаговый диалог) |
| `/cart`, `/checkout`, `/clearcart` | корзина: посмотреть, отправить заявки на рассмотрение, очистить |
| `/bookings`, `/booking <id>` | список заявок и карточка заявки |
| `/submit <id>` | отправить черновик на рассмотрение |
| `/cancel [id]` | отменить текущий диалог или удалить свою заявку |
| `/approve <id>`, `/reject <id>` | одобрить или отклонить заявку (администратор) |
| `/persons` | список пользователей (администратор) |
| `/addperson <фамилия> <имя> <отчество> <роль>` | добавить пользователя; роли: `STUDENT`, `TEACHER`, `ADMIN` (администратор) |

Команды администратора показываются в меню Telegram только после входа администратора.
Полный список — команда `/help`.

### Как это работает
- Бот принимает сообщения и нажатия кнопок через long polling, пересылает запросы в бэкенд и показывает ответ.
- В каждом запросе к бэкенду передаётся заголовок `Person-Id` с ИСУ пользователя, по нему бэкенд проверяет права.
- Правила (права, вместимость, пересечения по времени, статусы заявок) проверяет бэкенд. Бот только показывает результат и превращает ошибки бэкенда в понятные сообщения: нет прав, помещение занято, слишком много запросов, функция временно недоступна.
- Бот хранит в памяти только сессии чатов: кто вошёл и на каком шаге диалога. После перезапуска бота нужно снова выполнить `/login <ИСУ>`.

### Запуск
Нужны: JDK 21, запущенный бэкенд (см. его инструкцию: Redis и PostgreSQL в Docker, затем `./gradlew bootRun` в папке `lab1-nosql`) и токен бота.

1. Создать файл `.env` в корне проекта (он в `.gitignore`):
   ```
   TELEGRAM_BOT_TOKEN=<токен бота>
   BACKEND_URL=http://localhost:8080
   ```
2. Запустить бота:
   ```bash
   ./gradlew bootRun
   ```
3. В Telegram открыть бота, выполнить `/start`. Администратор из начальных данных бэкенда входит командой `/login 100000`.

| Настройка | По умолчанию | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | нет, обязательна | токен бота |
| `BACKEND_URL` | `http://localhost:8080` | адрес бэкенда |
| `server.port` в `application.yml` | `8081` | порт самого бота (health: `/actuator/health`) |

Для работы нужен доступ к `api.telegram.org`.
### Структура
```
src/main/java/com/university/booking/
├── client/BackendClient          запросы к бэкенду и перевод ошибок в сообщения
├── commands/                     команды (user/ и admin/)
├── service/dialog/               пошаговые диалоги: регистрация и бронирование
├── service/routing/              приём сообщений и кнопок, маршрутизация
├── ui/Buttons                    inline-кнопки
├── state/                        сессии чатов (в памяти)
├── dto/, exception/              объекты обмена с бэкендом и ошибки
└── configuration/                токен бота и HTTP-клиент
```
